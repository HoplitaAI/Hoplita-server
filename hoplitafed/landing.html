A tour of the real thing

Every picture is the application itself, running against real models and a real federation server. Drag, scroll the strip, or pick a chapter.

Chat that does the work

More than two hundred tools, and a bar for «done»

  • Agentic by default: web search, scraping, a browser it drives, files, shell, PDF and images, Word, Excel and PowerPoint, notes, tasks, calendar, and charts on a live canvas.
  • You watch it think: the model keeps a live intent list; a stall is caught by progress and time, and answered — with a question, a council, another model, or an honest close.
  • A reviewer checks the answer before you see it. /verify <command> keeps the turn going until the command passes.
  • Tabs, each its own world: conversation, model, reviewer, firewall and project.

Several models, one assistant

A pool of models, and a router that picks

  • Your models, in plain words: each one with a profile — heavy coding, vision, quick chat. One is the base; every job can run on its own.
  • The router reads each request and sends the turn to the model that fits, and says where it went. /model pins one by hand.
  • The Council: several models deliberate on any matter — answer, examine, reformulate — and vote.
  • Orchestration: a planner splits a task into sub-agents, each on its own model, and runs them after you approve the plan.

Agents at work

A plan you can watch run

Ask for something big and the planner splits it into sub-agents, laid out by stage: the ones that can run together, run together; the ones that need their results wait for them. You approve the plan first — edit a goal, drop a card, move one to another model or to a contact's machine — and then watch every card's light, its own intent list and the data flowing along the arrows.

Code

A coding environment, not a chat about files

Open a repository and the agent works in it: it reads, patches, runs your checks and commits on a branch first. You review every hunk — keep it or throw it away — with history, symbols from the language server, search and git checkpoints to go back to.

Whiteboard

A whiteboard that explains the code

One click and a model reads the repository and draws it: how it works, what the last commit changed, or what is on your desk right now — as a story in sections, with flow diagrams whose every node opens the exact lines it talks about, and the real diff next to the words. It follows the code: when the branch moves on, the board says so and brings itself up to date.

Federation

Share with people, not with a server

Add a contact by handle. Share a notes folder, a task project, a code repository — or open a session with a contact's agent and ask it what only it knows, within the permissions they gave you. Everything is sealed on your machine to the recipient's key before it leaves. Contacts and shares count because you signed them: a server that lies about who is whose contact is caught, not believed.

Remote sessions

Talk to a contact's agent

Right-click a contact and open a session: a green tab appears, and on the other side of it is their agent, on their machine, with their model, their calendar, their notes. It answers what only it knows, within the permission they gave you — straight away, after they review your request, or not at all — and every step of its turn comes back to your tab as it happens. The same door works the other way round: a contact's question to your agent opens a red tab on your screen.

Organized, and on schedule

Projects you can see, jobs that think

  • Projects as lists, boxes with their progress, a dependency graph and a timeline — and the model sees the same graph you do. A task whose dependencies are not done yet says so on its box: ⛔ 1/3.
  • Cron jobs run as full agentic turns: at a time, every so often, or at every start. Dislike a result and the supervisor rewrites the job.
  • Notes, tasks and appointments the agent reads and writes.

Yours, and in check

Encrypted at rest, fenced at every door

  • One SQLCipher database for notes, tasks, credentials, memory and settings, encrypted with your master password.
  • A credential vault with TOTP: the agent logs in without the password ever reaching the prompt.
  • A tool firewall, global and per tab, enforced on every path a call can take.
  • A memory that curates itself — facts, lessons and experience you can read, edit and wipe.

Hoplita server

Run your own federation

The server is a relay that cannot read what it carries: accounts, public keys, presence and mailboxes of sealed envelopes, pushed over a WebSocket the moment they arrive and forgotten once delivered. Losing it is an outage, not a leak.

  • Login by proof of private key — the server seals a nonce only the key holder can open
  • Invite-only sign-up by default, quotas per group, an admin for the operator
  • One script deploys it with PostgreSQL, Caddy and TLS, and an acceptance gate that checks it
